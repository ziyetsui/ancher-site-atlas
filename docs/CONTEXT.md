# CONTEXT — what this repo is, why it exists, and where everything lives

> For a future agent (or human) picking this up cold. Read this + `../CLAUDE.md`
> first. `CLAUDE.md` = how to work in the repo; this = the story and the map.

## The big picture

Ancher is building an **AI personal-website generator**: a user gives a little
about themselves (a sentence, links, a photo) and an agent produces a beautiful,
distinctive personal site. The hard problem isn't "make a page" — it's making it
**not generic** (diverse, with a point of view) while keeping a **quality floor**.

The strategy (see wiki docs below) is a **layered hybrid**:

```
diversity = visual direction  ×  module/structure  ×  content angle
```

Each layer is *curated* (so there's a quality floor) but *combinable* (so there's
diversity). This repo — **the Style Atlas** — is the curated素材 for two of those
layers (visual **directions** and structural **modules**), plus the copy-pasteable
**prompts** that generate them. It doubles as an **eval set** for the real generator:
each direction's `sample.png` is a screenshot of *its own* generated `index.html`, so
if the screenshot is wrong, the spec is wrong.

This atlas is the **prototype / reference**. The real generation will live in the
backend (`ancher/api`); for now we stand in for that backend with subagents/workflows
(an agent that can write frontend == the generator). The plan is to later tune the
real backend agent to reproduce these prompts' output quality.

## What was built (build log)

Built in one push (2026-06-03). Repo: `streamify-one/ancher-site-atlas`.

1. **5 seed directions** — editorial, swiss-minimal, warm-personal, technical-mono,
   bold-brutalist. Each = `prompt.md` (copy-apply artifact) + `DESIGN.md` (tokens) +
   self-generated `index.html` + `sample.png`. Generated by fan-out subagents acting
   as the generator.
2. **Browse site** (`site/`) — catalogue gallery (`index.html`) + a **viewer shell**
   (`view.html`) that iframes a direction page and adds back / prev-next so pages
   interlink (no orphans). `build_registry.py` scans `DESIGN.md` frontmatter →
   `registry.json` with artifact validation.
3. **Codex review pass** — ran `codex` over the seed; applied 5 fixes (local-serve
   paths, reduced-motion smooth-scroll, registry validation, tab a11y, copy fallback),
   deferred 3 with reasons.
4. **Photo + toggle** — each page got a user-photo slot + a bottom-right "照片 Photos
   On/Off" toggle (default On) to evaluate "does this design *need* a photo". Seed 5
   use `thispersondoesnotexist` faces (kept as-is).
5. **Module atlas** — 24 modules / ~52 variants across 5 categories (identity, trust,
   narrative, conversion, personality), each a self-contained specimen sheet (all
   variants in one file, neutral shared tokens). Browse at `site/modules.html`. Built
   by a 24-agent workflow.
6. **Expansion 5 → 17 directions** — +12 new (fashion-luxe, editorial-dark,
   vibrant-gradient, retro-print, neo-saas, dark-luxe, playful-rounded, mono-zine,
   art-gallery, organic-natural, cinematic-dark, newsprint), generated by a 12-agent
   workflow, using the artistic images in `assets/`.
7. **Asset library** — 34 AI placeholder images compressed to webp (117MB → 11MB),
   renamed to descriptive slugs, with `assets/MANIFEST.md` + `_manifest.json`.
8. **Coverage analysis** vs awesome-design-md — see `COVERAGE.md`.
9. **Experimental batch (17 → 27 directions)** — added the illustration-rich-brand
   gap + 9 styles neither design-md nor we had: glassmorphism, memphis-postmodern,
   y2k-vapor, handcrafted-sketch, maximalist-collage, soft-3d-clay, art-deco,
   risograph, athletic-sport. Glass/3D/Y2K are pure CSS (no WebGL). Used
   previously-unused `assets/` images.
10. **docs/** — this folder (CONTEXT / DECISIONS / COVERAGE) so future agents have
   the why + the repo map.
11. **Skin Lab** (`site/skins-lab.html` + `skins.json`) — answer to "the module atlas
   is bland/one-palette": a token contract + per-direction skins, so one set of modules
   re-skins live (module × direction matrix, no 648 static pages). Prototype: 5 skins ×
   5 modules. First cut of the cross-atlas plan.
12. **In-context component inspector** — the viewer's 组件 toggle now decomposes the page
   you're actually looking at: outlines + labels each `[data-module]` section in place +
   a side panel with explanations. All 27 direction pages tagged with
   `data-module`/`data-variant` (124 sections) by two workflows.
13. **Vercel hosting** — deployed as a standalone static site at
   **https://ancher-site-atlas.vercel.app** (`vercel.json`: `/`→`/site/` + `.md`/`.json`
   utf-8 charset). Redeploy with `vercel deploy . --prod --yes`.
14. **Text Motion Lab** (`site/motion-lab.html`) — a 4th browse surface (gallery tab
   「文字动效」) showcasing 23 text-animation patterns in two registers: **01–10** base
   effects (typewriter, blur-in, glitch, scramble, flip, slice, stroke-draw, highlight-sweep,
   elastic, depth-shift) and **11–23 extracted from the 27 direction pages' own motion**
   (jitter, riso-misregister, sticker-pop, neon-glow, underline-draw, marquee, tilt-in,
   reveal-stack, scanlines, blob-morph, clay-float, pulse-dot, button-press — each crediting +
   linking its source direction). Each pure HTML/CSS/JS, no deps. Self-contained single file;
   「复制整页源码」copies all 23 for reuse. Motion layer for the generator (the prompts can
   ask for these by name).
15. **Image Lab** (`site/image-lab.html`, tab「图像处理」) — 原图 → prompt → CSS → 效果:
   real framed photos auto-fit + per-module image slots, the image-treatment layer.
16. **GSAP Motion Lab** (`site/gsap-lab.html`, tab「GSAP 动效」) — the **JS-driven motion** layer
   on **vendored GSAP 3.13** (`vendor/gsap/`, all bonus plugins, no CDN; designed via
   `docs/superpowers/specs/2026-06-03-gsap-lab-design.md` + a codex review). Two surfaces in one
   hub page: ① **14 full-page demos** (`gsap-demos/<id>/`), each an original style × a plugin
   cluster (SplitText / ScrollTrigger pin·scrub·parallax / ScrollSmoother / Flip / Draggable+Inertia /
   DrawSVG / MorphSVG / MotionPath / ScrambleText / Physics2D / Observer), registry-driven
   (`gsap_registry.json` from each demo's `meta.json`), screenshot → live iframe viewer; ② **54
   effect cards** (`site/gsap-cards/<family>.js` → `window.GSAP_CARDS`, contract in `CONTRACT.md`),
   grouped by plugin, auto-play in-view, each with 复制 Prompt + 复制代码. Built by a 29-agent
   fan-out workflow; internal素材 / eval set. (Gotcha learned: load GSAP at end of `<body>` — Flip's
   `_initCore` is body-dependent, registering in `<head>` strands it. See DECISIONS D13.)

## How to continue (the repeatable move)

Adding directions/modules is a fan-out: one subagent per item, each reads
`directions/editorial/{DESIGN.md,prompt.md}` for the format + copies an image from
`assets/`, then writes `DESIGN.md` + `prompt.md` + `index.html` (with the photo+toggle
contract). Then screenshot each (photos ON, scroll to fire reveals) → `sample.png`,
run `python3 scripts/build_registry.py`, verify the gallery. See `CLAUDE.md` + the wiki
exec doc §7 for the phased plan, and `COVERAGE.md` for *which* directions to add next.
